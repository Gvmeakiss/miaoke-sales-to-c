# 销售 ToC 核对项目

本项目用于核对 2026-01-01 至 2026-06-30 的销售 ToC 数据链：

`旺店通订单 → 惠策对账明细 → 惠策店铺汇总 → OMS 月结 Y001 → SAP 标准发票（2C）`

上述为业务数据获取与处理路径；正式审计底稿总览以SAP收入确认端为起点，按 `SAP开票 → OMS月结 → 惠策账单汇总 → 惠策账单明细 → 旺店通订单` 向业务源头逐层穿透。

当前工作区按“原始输入、正式交付、可复现代码、可复算数据、过程归档”五层管理。历史 V2/V3/V4/V4.1、修复版及demo不再作为正式版本使用；本轮检查日志和中间结果统一归档至`archive/20260804/`。

## 2. 数据范围与来源

- 账单及财务核对期间：2026-01-01 至 2026-06-30，含首尾。
- 旺店通正式匹配期间：2026-01-01 至 2026-06-30。2025年12月及11月订单仅用于Cut-off敏感性分析，不纳入正式匹配结果。
- 旺店通：`input/旺店通订单清单/`，订单表头及商品明细。
- 惠策明细：`input/惠策系统对账单清单/`，共 15 份订单级对账明细。
- 惠策汇总：`input/惠策系统对账单汇总/`，共 19 份店铺级月度汇总；其中`对账店铺汇总6月-3.xlsx`为客户补充的遗漏记录。
- OMS：`input/OMS 系统日结月结查询记录：25年12月到26年6月2C单据.sql`。
- SAP：`input/发票清单：26.01.01-26.06.30/`。
- 旺店通店铺主数据：`input/旺店通内店铺id与店铺名称映射.csv`，用于店铺 ID—OMS 客户优先映射。

原始资料不随核对过程修改。当前惠策明细和汇总导出均没有物料、SKU或商品数量字段。

## 3. 核对逻辑

### 3.1 旺店通订单—惠策明细

- 核对基表：2026年1—6月惠策导出账单清单；不再按惠策业务日期过滤订单—账单核对池。
- 正式订单候选池：仅使用2026-01-01至2026-06-30的旺店通订单，同时参考有效交易/付款日期及发货日期。
- Cut-off敏感性分析另行读取`input/旺店通订单清单/25年11月/`下4个文件，不写入或覆盖正式订单候选池；11月文件为85列，核心订单号、金额、数量、店铺、日期及状态字段完整，可用于订单—账单敏感性分析。
- 强键：`旺店通原始单号 = 惠策平台订单号`。
- 二级辅助证据：强键未命中时，如同一旺店通内部订单号下至少存在一笔已命中惠策的平台订单号，且待解释平台订单的旺店通分摊金额为零，则分类为“同内部订单零金额附属单”。该规则只解释订单/数量覆盖，不将零金额记录计入金额匹配。
- 分类原则：平台订单号精确匹配及同内部订单零金额附属单分别列示，其他订单按核对分类展示。
- 映射粒度：一行一个平台订单号，同时保留旺店通内部订单号集合、惠策对账流水号集合、店铺及月份。
- 金额口径：旺店通平台订单分摊金额 `allocated_total` 与惠策实际实收净额比较；惠策实际实收净额=收款金额（正实收）-退款金额（负实收）。旺店通金额仅作为订单—账单桥接金额，不作为最终收入确认金额。
- 正式范围完整平台订单并集为 5,896,663 行，保存在 `reconciliation/results/order_bill_recon.csv`；正式Excel不再嵌入该过程明细页，仅在汇总页列示分类金额。

### 3.2 惠策明细—惠策店铺汇总

- 共同维度：导出结算月份 + 平台 + 店铺。
- 主口径：惠策账单清单实际实收净额与惠策店铺汇总实际结算金额核对。
- 惠策账单清单实际实收净额=收款金额（正实收）-退款金额（负实收）；惠策店铺汇总实际结算金额=成功金额+不一致实收金额+单边实收金额。

### 3.3 惠策店铺汇总—OMS 月结

- 惠策没有物料字段，按月份 + 惠策店铺/OMS客户映射核对金额。
- 店铺映射优先使用旺店通店铺 ID—名称主数据，并以 OMS 客户编码核验；主数据未覆盖的店铺继续使用现有名称/交易匹配逻辑兜底。
- 客户另行确认的 `快团团供应商→817722`、`快团-妙可蓝多奶酪星球→813210` 作为更高优先级的客户确认映射；OMS SQL 中无对应交易的组合按账单单边记录列示。
- 惠策店铺汇总实际结算金额与OMS `share_amount` 结算金额为主口径。
- 同一客户跨月累计仅解释结算时点，不替代逐月匹配。
- 不执行“OMS未开票池—惠策”核对。

### 3.4 数量链

- Step 1：惠策无原生商品数量，以惠策平台订单号连接旺店通商品明细取得账单订单证据数量，并与 OMS `item_num` 按发货月份 + 店铺/客户 + SAP物料核对。
- Step 2：OMS 与 SAP 按销售单号 + 物料编码 + 销售单位核对双方原生数量。
- 正式底稿不进行旺店通、惠策、OMS、SAP四方数量直接比较，数量差异按上述两段业务流分别列示。

### 3.5 OMS 月结—SAP

- 强键：OMS销售单号 + 物料编码 + 销售单位。
- 同时比较数量和含税金额。
- 一致键用于双向补充客户、月份、发票号等字段；双方单边记录完整保留。

## 4. 关键结果

- 惠策账单平台订单 5,769,505；2026年度旺店通候选平台订单 4,728,414；平台订单号直接命中 4,601,256；惠策账单订单匹配覆盖率 79.75%；同内部订单零金额附属单 41,021。
- 正式范围订单—账单金额一致订单共4,204,532组；对应惠策账单实际实收为243,122,621.11元、旺店通订单桥接金额为243,122,622.15元，差异1.04元，金额匹配率为100.00%。全量比对口径下，旺店通分摊金额为268,424,590.67元、惠策明细实际实收为275,333,617.04元，金额匹配率为97.49%；该惠策全量金额与后续惠策内部核对直接勾稽。
- 惠策明细—汇总共164个“结算月+平台+店铺”组合，明细实际实收与汇总实际结算金额均为275,333,617.04元。
- 惠策店铺汇总实际结算金额为275,333,617.04元；OMS月结 `share_amount` 为280,247,849.59元；金额匹配率为98.25%。
- SAP开票全量金额为289,523,056.34元，OMS月结全量金额为280,247,849.59元，金额匹配率为96.80%；全量数量分别为18,698,382和17,870,519，数量匹配率为95.57%。
- OMS—SAP共同键金额分别为280,229,211.04元及280,229,212.42元，差异1.38元，匹配率为100.00%；共同键双方数量均为17,868,882。
- Step 1账单订单证据数量为17,479,970，OMS月结数量为17,870,519，差异390,549，差异率2.19%。
- Step 2 OMS—SAP共同键双方数量均为17,868,882，差异为0。
- Cut-off核对使用惠策明细`business_date（业务日期）`：2026-06-28共60,938笔、净实收1,515,653.87元；2026-06-29共74,600笔、净实收2,057,089.79元。统计采用与总体核对一致的全量状态范围和`收款金额-退款金额`口径；截至2026年6月30日，惠策系统未生成当日账单记录。
- 店铺映射表纳入旺店通店铺 ID 主数据及客户确认映射；正式展示仅保留店铺、OMS客户编码和映射依据，金额核对统一采用实际结算口径。
- 客户确认映射覆盖 12 个惠策店铺月度组合；813210 在本次 OMS SQL 中无交易记录，对应组合按账单单边记录列示。
- 旺店通期间敏感性分析显示：仅2026年度、追溯至2025年12月及追溯至2025年11月的惠策金额一致覆盖率分别为88.3011%、91.0375%及91.0383%，平台订单号覆盖率分别为79.75%、82.13%及82.38%。11月口径较12月口径新增659,009个旺店通平台订单及45,992,914.20元，金额覆盖率增量较小，订单号覆盖率提高0.25个百分点。

## 6. 重跑方式

### 6.1 使用现有数据库刷新正式结果

```bash
python3 reconciliation/reload_wdt_orders.py
python3 reconciliation/reconcile_sales_flow.py --output-dir reconciliation/results
python3 reconciliation/analyze_wdt_cutoff_sensitivity.py
```

生成 Excel 时需使用 Codex 工作区提供的 Node.js 与 `@oai/artifact-tool` 依赖。构建脚本会在临时目录建立依赖链接，完成后自动清理：

```bash
WORKSPACE_NODE='<workspace-node>' \
WORKSPACE_NODE_MODULES='<workspace-node_modules>' \
  reconciliation/build_workpaper.sh
```

### 6.2 从原始资料全量重建

```bash
python3 reconciliation/reconcile_sales_toc.py \
  --input input --work reconciliation/work \
  --output reconciliation/intermediate/base --rebuild

python3 reconciliation/explore_wdt_oms_matching.py
python3 reconciliation/reconcile_huice_oms.py
python3 reconciliation/reload_wdt_orders.py
python3 reconciliation/reconcile_sales_flow.py --output-dir reconciliation/results
```

全量重跑体量较大。完成后应检查：

1. `reconciliation/results/summary.json` 控制数是否与本README关键结果一致。
2. Excel公式错误扫描是否为0。
3. 10个正式工作表页面预览是否完整、无截断；订单—惠策全量过程明细页、月度全流程分析页及解释性规则页不纳入正式交付工作簿。
4. XLSX压缩结构检查是否通过。

## 7. 维护原则

- `input/`、正式底稿及当前数据库不得作为临时目录使用。
- 新测试统一写入 `reconciliation/intermediate/`，验证后可整体删除。
- 不再新增 V2/V3/V4 等并行版本目录；正式结果直接覆盖 `reconciliation/results/` 和正式底稿。
- 需保留历史过程资料时，在`archive/YYYYMMDD/`建立独立只读归档，不与正式交付目录混放，也不覆盖既有归档。
