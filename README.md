# 销售 ToC 核对项目

本项目用于核对 2026-01-01 至 2026-06-30 的销售 ToC 数据链：

`旺店通订单 → 惠策对账明细 → 惠策店铺汇总 → OMS 月结 Y001 → SAP 标准发票（2C）`

当前目录仅保留新版正式交付物、原始输入、可复现脚本、当前数据库及完整核对结果。历史 V2/V3/V4/V4.1、修复版、demo、旧检查日志及可重建测试输出已清理。

## 1. 项目结构

## 2. 数据范围与来源

- 账单及财务核对期间：2026-01-01 至 2026-06-30，含首尾。
- 旺店通订单追溯期间：2025-12-01 至 2026-06-30，用于覆盖12月下单/发货、次年1月确认收货后出账的跨期订单。
- 旺店通：`input/旺店通订单清单/`，订单表头及商品明细。
- 惠策明细：`input/惠策系统对账单清单/`，共 15 份订单级对账明细。
- 惠策汇总：`input/惠策系统对账单汇总/`，共 19 份店铺级月度汇总；其中`对账店铺汇总6月-3.xlsx`为客户补充的遗漏记录。
- OMS：`input/OMS 系统日结月结查询记录：25年12月到26年6月2C单据.sql`。
- SAP：`input/发票清单：26.01.01-26.06.30/`。
- 旺店通店铺主数据：`input/旺店通内店铺id与店铺名称映射.csv`，用于店铺 ID—OMS 客户优先映射。

原始资料不随核对过程修改。当前惠策明细和汇总导出均没有物料、SKU或商品数量字段。

## 3. 核对逻辑

### 3.1 旺店通订单—惠策明细

- 核对基表：2026年1—6月惠策导出账单清单；不再按惠策业务日期过滤订单—账单核对池。
- 订单候选池：向前追溯2025-12-01至2026-06-30的旺店通订单，同时参考有效交易/付款日期及发货日期。
- 强键：`旺店通原始单号 = 惠策平台订单号`。
- 二级辅助证据：强键未命中时，如同一旺店通内部订单号下至少存在一笔已命中惠策的平台订单号，且待解释平台订单的旺店通分摊金额为零，则分类为“同内部订单零金额附属单”。该规则只解释订单/数量覆盖，不将零金额记录计入金额匹配。
- 分类原则：平台订单号精确匹配及同内部订单零金额附属单分别列示，其他订单按核对分类展示。
- 映射粒度：一行一个平台订单号，同时保留旺店通内部订单号集合、惠策对账流水号集合、店铺及月份。
- 金额口径：旺店通平台订单分摊金额分别与惠策本期应收、本期实收比较；订单应收仅作为辅助证据。
- 完整平台订单并集为 6,267,791 行，保存在 `reconciliation/results/order_bill_recon.csv`。
- Excel 第 3 页（`3.旺店通-惠策订单核对明细`）分层展示 18,000 行，其中单独列示零金额附属平台单样本、一致记录、金额比较结果及双方单边记录。

### 3.2 惠策明细—惠策店铺汇总

- 共同维度：导出结算月份 + 平台 + 店铺。
- 主口径：全量应收和全量实收分别核对。
- 汇总“对账成功金额”与明细“对账状态=对账成功”定义不同，不作为内部主钩稽口径。

### 3.3 惠策店铺汇总—OMS 月结

- 惠策没有物料字段，按月份 + 惠策店铺/OMS客户映射核对金额。
- 店铺映射优先使用旺店通店铺 ID—名称主数据，并以 OMS 客户编码核验；主数据未覆盖的店铺继续使用现有名称/交易匹配逻辑兜底。
- 客户另行确认的 `快团团供应商→817722`、`快团-妙可蓝多奶酪星球→813210` 作为更高优先级的客户确认映射；OMS SQL 中无对应交易的组合按账单单边记录列示。
- 惠策对账成功分类金额为主，应收、实收作为并列辅助口径。
- 同一客户跨月累计仅解释结算时点，不替代逐月匹配。
- 不执行“OMS未开票池—惠策”核对。

### 3.4 数量链

- 惠策平台订单数是惠策原生订单数量。
- “惠策覆盖订单派生数量”由平台订单号连接旺店通商品明细取得，不代表惠策原生商品数量；其中区分平台订单号直接命中的数量，以及由同一内部订单零金额附属单解释的数量。
- 派生订单数量与 OMS 按发货月份 + 店铺/客户 + SAP物料进行多对一核对。
- OMS 与 SAP 按销售单号 + 物料编码 + 销售单位核对原生数量。

### 3.5 OMS 月结—SAP

- 强键：OMS销售单号 + 物料编码 + 销售单位。
- 同时比较数量和含税金额。
- 一致键用于双向补充客户、月份、发票号等字段；双方单边记录完整保留。

## 4. 关键结果

- 惠策账单平台订单 5,769,505；旺店通候选平台订单 5,236,612；平台订单号直接命中 4,738,326；惠策账单订单匹配率 82.13%；同内部订单零金额附属单 42,634。
- 2025年12月订单与2026年1月惠策账单直接命中153,414组，验证了跨期确认收货后出账对原期间过滤的影响。
- 旺店通候选订单证据率为91.30%；已匹配平台订单对应惠策本期应收349,669,685.35元，占惠策账单全量本期应收89.18%。
- 旺店通比对金额 260,397,231.08 元；对应惠策金额（用于旺店通比对）260,397,235.01 元，已匹配范围金额一致率为 100.00%；惠策汇总表全量本期应收金额为 392,084,906.47 元。
- 惠策明细—汇总共164个“结算月+平台+店铺”组合，应收及实收匹配率均为100.00%。
- 惠策成功分类金额 283,828,575.43 元；OMS月结金额 280,247,849.59 元；总体金额匹配率 98.74%。
- 旺店通本期发货商品数量 17,858,650；平台订单号直接命中的派生数量 17,306,940；零金额附属单解释数量 173,030；订单证据覆盖数量 17,479,970，覆盖率 97.88%；OMS月结数量 17,870,519。
- OMS—SAP一致键双方数量 17,868,882；OMS数量覆盖率 99.99%。
- 店铺映射表纳入 31 个旺店通店铺 ID 主数据映射；其应收口径覆盖 391,823,432.07 元，另有客户确认映射覆盖 91,820.92 元，合计高置信映射金额 391,915,252.99 元。
- 客户确认映射覆盖 12 个惠策店铺月度组合；813210 在本次 OMS SQL 中无交易记录，对应组合按账单单边记录列示。

## 6. 重跑方式

### 6.1 使用现有数据库刷新正式结果

```bash
python3 reconciliation/reload_wdt_orders.py
python3 reconciliation/reconcile_sales_flow.py --output-dir reconciliation/results
```

生成 Excel 时需使用 Codex 工作区提供的 Node.js 与 `@oai/artifact-tool` 依赖。构建脚本会在临时目录建立依赖链接，完成后自动清理：

```bash
WORKSPACE_NODE='<workspace-node>' \
WORKSPACE_NODE_MODULES='<workspace-node_modules>' \
  reconciliation/build_workpaper.sh
```

### 6.2 从原始资料全量重建

```bash
python3 reconciliation/reconcile_sales_toc.py \
  --input input --work reconciliation/work \
  --output reconciliation/intermediate/base --rebuild

python3 reconciliation/explore_wdt_oms_matching.py
python3 reconciliation/reconcile_huice_oms.py
python3 reconciliation/reload_wdt_orders.py
python3 reconciliation/reconcile_sales_flow.py --output-dir reconciliation/results
```

全量重跑体量较大。完成后应检查：

1. `reconciliation/results/summary.json` 控制数是否与本README关键结果一致。
2. Excel公式错误扫描是否为0。
3. 12个工作表页面预览是否完整、无截断；业务流程与单对单规则已合并至全局总览，不再单列OMS—SAP字段映射明细及完整明细索引页。
4. XLSX压缩结构检查是否通过。

## 7. 维护原则

- `input/`、正式底稿及当前数据库不得作为临时目录使用。
- 新测试统一写入 `reconciliation/intermediate/`，验证后可整体删除。
- 不再新增 V2/V3/V4 等并行版本目录；正式结果直接覆盖 `reconciliation/results/` 和正式底稿。
- 需保留历史版本时，应在项目外归档，不放回当前工作目录。
